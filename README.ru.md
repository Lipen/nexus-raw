# nexus-raw

**`nxr` — это curl для raw-репозитория Sonatype Nexus.**
Публикации, завершённость которых доказуема, переносы, которые докачиваются сами собой, и модель отказов, которой скрипты могут доверять.

## Зачем

Raw-репозитории Nexus — это место, где сборки обслуживают шелл-скрипты.
Один цикл `curl -T` заливает, другой `curl` скачивает, а человек вглядывается в вывод, чтобы угадать, долита ли версия.
Дайджесты никто не проверяет, докачки нет, и наполовину залитая версия выглядит ровно как готовая.

`nxr` заменяет этот стек.
Одна команда публикует каталог, одна забирает его назад, и обе говорят правду.
URL в argv, креды из `-u` или окружения: каждый вызов самодостаточен, конфиг-файла нет, на сервере ничего ставить не нужно.
Те же операции доступны как Rust-библиотека (`nexus-raw-core`) и как Node-биндинги.

| Ваш curl-конвейер | nxr |
|:--|:--|
| `curl -T` по файлу, потом надежда | `nxr up dist/1.4.0/ $BASE/1.4.0/` — скан, дифф, параллельная заливка, маркеры |
| Наполовину залитая версия выглядит опубликованной | Завершённость доказана сиблингами `<name>.sha256`, а не надеждой |
| Обрыв заливки = прогонять цикл заново | Повторите ту же команду: завершённое пропускается |
| Проверка digest'ов живёт в рукописном манифесте | Сиблинги выходят в обычном формате `sha256sum -c`, генерируются сами |
| Причины отказа различают грепом вывода | Exit-коды 0/1/2/3, `hint:` у каждой ошибки, потоки NDJSON-событий |

## Быстрый старт

Опубликовать версию, назвать её каналом, забрать назад и проверить офлайн:

```bash
BASE=https://nexus.example.com/repository/raw-main

# что могут забирать потребители: down без этого файла в каталоге версии откажется
printf '{"artifacts": ["app-1.4.0.zip"]}\n' > dist/1.4.0/manifest.json

# публикация каталога версии: маркеры генерируются, проверяются и загружаются сами
nxr up dist/1.4.0/ "$BASE/1.4.0/"

# назвать — канал это токен-файл с любым именем
nxr channel set "$BASE/latest" 1.4.0 --if-forward

# забрать в другое место: канал называет версию, манифест перечисляет файлы
V=$(nxr channel get "$BASE/latest")
nxr down "$BASE/$V/" vendor/prebuilt
nxr verify vendor/prebuilt
```

Прерванная передача доканчивается повтором той же команды.
`up` пропускает уже завершённое, `down` докачивает с part-файлов через `Range: bytes=N-` по умолчанию, а `--fresh` — осознанный старт с нуля.

## Что вы получаете

**Заточено под плохие сети**
- Ретраи, stall-детект и таймауты соединения встроены, а не прикручены сбоку.
- `down` докачивает через part-файлы и `206`; `up` перед записью перепроверяет завершённость.
- Клиент прогнан на конформанс против `mock-nexus` — сервера отказов на чистом std с 11 сценариями: обрывы соединений, частичные PUT, медленные куски, auth-стены.

**Завершённость, которую можно доказать**
- У каждого опубликованного объекта есть сиблинг `<name>.sha256` в формате `sha256sum -c`: генерируется по умолчанию, `--no-sha` — осознанный отказ.
- Расходящийся завершённый артефакт отвергается, а не перезаписывается.
- `nxr verify` проверяет байты, маркеры и digest'ы офлайн, без обращения к серверу.

**Поверхность, на которую опираются скрипты**
- Exit-коды что-то значат: 0 ок, 1 данные, 2 misuse, 3 транспорт — CI отличает «перекачать» от «сервер лежит».
- Каждая ошибка печатает `hint:`; `--json` отдаёт один объект для простых команд и NDJSON-события для переносов.
- TLS проверяется по умолчанию, и `--tls-insecure` — единственный выключатель.
- Креды берутся из `-u`, `NXR_AUTH` или `NXR_USERNAME` + `NXR_PASSWORD`, именно в этом порядке; `nxr doctor` называет сработавший источник, не печатая значений.

<details>
<summary>Примеры настройки креденциалов</summary>

```bash
# простой путь: две переменные, ничего кодировать не надо
export NXR_USERNAME="my-login"
export NXR_PASSWORD="my-password"

# путь для CI: одно значение вместо двух, удобно для маскируемой переменной
export NXR_AUTH="$(printf '%s:%s' 'my-login' 'my-password' | base64)"
# base64 от "my-login:my-password": bXktbG9naW46bXktcGFzc3dvcmQ=
```

`-u` быстрее всего для разового вызова и виден в `ps`.

</details>

## Команды

| Команда | Делает |
|:--------|:-------|
| `nxr get <URL> [-o FILE] [--continue]` | GET в файл (через `.part`, докачка через Range) или stdout |
| `nxr put <URL> -f FILE [--sha]` | PUT байтов: `--sha` ещё и PUT `.sha256`-сиблинга |
| `nxr head <URL>` | статус, размер, content type |
| `nxr sha <FILE\|URL>` | потоковый sha256 файла или удалённого объекта |
| `nxr up <SRC_DIR> <DST_URL> [--manifest F] [--no-sha] [--dry-run] [--claim-first NAME]` | скан → дифф → PUT байтов + маркеров параллельными воркерами |
| `nxr down <SRC_URL> <DST_DIR> [--manifest F\|URL\|-] [--name N]... [--ls] [--fresh]` | перечисление → дифф → поток+hash → rename + локальный маркер |
| `nxr ls <URL> [--assets]` | листинг версий или объектов через search API (experimental) |
| `nxr channel get <URL>` | токен канала (`unset`, если пусто) |
| `nxr channel set <URL> <TOKEN> [--if-forward]` | запись токена, `--if-forward` допускает сдвиг только вперёд в dotted-numeric порядке |
| `nxr verify <DIR> [--manifest F\|-]` | локально байты + маркер + digest, без сети |
| `nxr doctor [URL]` | креды, TLS, настройки, достижимость |

`down` берёт перечисление явно: `manifest.json` в каталоге версии, `--manifest`, повторяемый `--name` или best-effort `--ls`.

## Интеграция

Три глубины, один контракт: шёллить `nxr`, встраивать `nexus-raw-core` в Rust, звать Node-биндинги.
Гайд с командами установки, сниппетами и правилами вендоринга: [docs/how-to/integrate.md](docs/how-to/integrate.md).

<details>
<summary>Устройство репозитория</summary>

| Путь | Для |
|:-----|:----|
| `crates/nexus-raw-core/` | Rust-библиотека из четырёх слоёв: `transport` + `primitive`, `sync`, `layout` и фасад `Nxr` |
| `crates/nexus-raw/` | бинарь `nxr`: только флаги, рендер и exit-коды, без протокольной логики |
| `crates/mock-nexus/` | мок-сервер с таблицей отказов, конформанс-фикстура |
| `docs/` + `mkdocs.yml` | сайт документации (zensical), поднимается `just docs` |
| `crates/nexus-raw-napi/` | Node-биндинги (npm-пакет `nexus-raw`), промисы над фасадом `Nxr` |

</details>

<details>
<summary>Разработка</summary>

```bash
just check        # fmt + clippy + prek + тесты: полный гейт
just test         # юнит- и конформанс-наборы
just mock atomic --port 8080
just nxr -- up dist/1.4.0/ http://127.0.0.1:8080/1.4.0/
just docs         # сайт документации, http://localhost:8000, live reload
```

Конформанс-наборы гоняют и `nexus-raw-core`, и бинарь `nxr` против `mock-nexus`.
Список сценариев в `crates/mock-nexus/src/lib.rs` — единственный источник: сценарий для одной реализации кладётся тем же коммитом вместе с её тестом.

</details>
